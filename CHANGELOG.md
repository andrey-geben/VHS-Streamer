# VHS-Streamer — журнал изменений

## v1.1.1 — большой релиз переносимости, стабильности и интерфейса

Первый релиз после 1.1.0, в который собраны все исправления и доработки.
Версии 1.1.2–1.1.13 из промежуточных сборок вошли сюда целиком.

### Переносимость (главная боль)

- **Пути считаются от папки программы**, а не от текущего каталога: архив,
  логи и конфиг больше не «уезжают» при запуске из ярлыка или планировщика.
- **Первый запуск**: `config.yaml` создаётся из `config.example.yaml`,
  пароль администратора генерируется случайно и печатается в консоль,
  `server.secret_key` тоже генерируется.
- **В дистрибутив не попадают чужие секреты**: `build_exe.bat` больше
  не копирует рабочий `config.yaml` разработчика.
- **`mediamtx.yml` очищается при старте** от путей другой машины
  (`runOnInit` с абсолютными путями к ffmpeg) — они создаются заново.
- **Установочный скрипт** `install.bat` добавляет правила брандмауэра:
  8100 (веб), 8081 (ONVIF), 8554 (RTSP), 8889 и 8189/UDP (WebRTC), 8080 (дубли).
- **`bin/` с MediaMTX и FFmpeg** входит в архив — работает без интернета.
  Если компонентов нет, приложение печатает понятную инструкцию, а не падает молча.

### Стабильность

- **Сторож MediaMTX**: если процесс упал, приложение поднимает его само
  и пишет об этом в лог.
- **Восстановление входящих путей**: сторож пересоздаёт пропавшие
  `__raw_<камера>` и сохраняет их в `mediamtx.yml`, чтобы они пережили
  перезапуск MediaMTX.
- **Зачистка процессов**: при остановке и при следующем старте гасятся
  осиротевшие `ffmpeg`/`mediamtx` из папки `bin\` (модуль `proc_tree.py`).
  `stop.bat` больше не убивает все `ffmpeg` системы, а гасит дерево процесса.
- **`/api/streams` не падает 500**, если API MediaMTX недоступен —
  приложение перезапускает его и повторяет операцию.

### PTZ

- Поддержка определяется автоматически: перебор портов ONVIF
  (80 → 8000 → 2020 → 8899), результат кэшируется.
- Единый определитель адреса для `move/stop/home/zoom` — раньше команды
  уходили на порт 80, хотя PTZ жил на 8899, и «работали» без эффекта.
- Можно задать вручную: `onvif_port` или `ptz_endpoint` у камеры.
- Причина отказа видна в логе и в консоли браузера (`[PTZ] ...`).

### Превью и потоки

- Плитка больше **не грузит MediaMTX напрямую**: открывается собственная
  страница `/player/<камера>`, которая показывает поток только когда
  входящий путь готов, иначе — «Нет сигнала». JSON-ошибки MediaMTX
  и панель браузера в кадре больше не появляются.
- Токен для MediaMTX стал **подписанным** (`itsdangerous`) и переживает
  перезапуск приложения — превью не остаются чёрными после рестарта.
- **Индикаторы исходящих потоков** на плитке, рядом с кнопкой архива:
  зелёный — поток работает (в подсказке число читателей), красный — не поднят;
  клик открывает конкретный поток на весь экран.
- Новые API: `/api/cameras/status` (онлайн + готовность входящего пути),
  `/api/streams/status` (состояние клонов).

### Интерфейс

- Единая тема `static/css/theme.css`: палитра, типографика, кнопки, формы,
  таблицы, скругления, состояния наведения и фокуса.
- **Две темы**: тёмная и светлая, переключатель в шапке и на странице входа,
  выбор запоминается, применяется до отрисовки.
- Компактная мозаика камер, служебная информация в шапке плитки,
  активный пункт меню.
- Общая страница входа в стиле приложения.
- HTML отдаётся с `Cache-Control: no-store`, service worker обновлён (`v2`),
  версия CSS поднимается при изменениях — старые стили больше не залипают.

### Обслуживание

- Флаги `--reset-auth` (вернуть `admin/admin`) и `--no-auth` (отключить вход).
- `reset_auth.bat` — тот же сброс в один клик, с русским текстом в консоли.
- `build_exe.bat` копирует в дистрибутив только нужное: `templates`,
  `mediamtx.yml`, `config.example.yaml`, скрипты запуска.

### Известные ограничения

- Аппаратное кодирование (QSV/NVENC/AMF) работает только при наличии
  соответствующего железа и драйверов; иначе используется `libx264`.
- Архив записей и `events.db` по-прежнему лежат рядом с программой —
  при обновлении папки их нужно сохранять.
