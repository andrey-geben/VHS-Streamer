Быстрый старт

  1. Запустите Streamer: start.bat / ./start.sh или службу vhs-streamer.
  2. Откройте http://<ip>:{{ port }} и войдите под учётной записью из config.yaml.
  3. При первом запуске пароль администратора генерируется автоматически и печатается в лог/консоль.
  4. Откройте Настройки → Камеры, добавьте IP-камеру по RTSP или найдите её через ONVIF/SADP.
  5. Проверьте поток на главной и при необходимости настройте архив, события и пользователей.

Камеры и потоки

Streamer принимает IP-камеры по RTSP/HTTP, USB/аналоговые устройства и ONVIF-камеры. Камера отдаёт поток один раз в MediaMTX, а MediaMTX размножает его на браузер, NVR и архив.

Для поиска в локальной сети доступны ONVIF WS-Discovery, SADP (Hikvision), SSDP/UPnP, Dahua/Amcrest broadcast и ISAPI-проба Hikvision. Дополнительные методы включаются галочками в Настройки → ONVIF.

Добавление IP-камеры

  1. Настройки → Камеры → Добавить.
  2. Укажите имя и RTSP-URL вида rtsp://user:pass@ip:554/stream.
  3. Проверьте кодек, разрешение и звук; сохраните.
  4. Для ONVIF используйте поиск камер, для аналоговых — карту захвата/USB.
Не ставьте одинаковый id разным камерам и не добавляйте одну камеру дважды под разными именами — это создаст дубли потоков и событий.

Архив

Архив — циклическая запись сегментами MP4. Запись разрешена только на подключённый внешний носитель: отдельный диск, NAS или смонтированный раздел. Системный диск и каталог программы не используются.

  • Путь задаётся в Настройки → Архив, например /mnt/vhs-archive.
  • Если путь не задан, не существует или указывает на системный диск — архив не активен.
  • Для каждой камеры выберите режим: постоянная или по событиям.
  • После смены общего пути перезапустите Streamer.
  • Следите за свободным местом: циклическая запись удаляет старые сегменты по лимиту размера/срока.

События и motion

Motion detection работает на OpenCV и не создаёт дополнительный поток с камеры. Включается глобально и может переопределяться для каждой камеры.

  • Настройте чувствительность (минимальную площадь) в настройках камеры.
  • События видны в разделе События и на главной; для тревожных событий есть снимок.
  • Режим записи «по событиям» пишет заданное число секунд вокруг срабатывания.
  • ONVIF-события приходят от камеры и не требуют OpenCV.

Пользователи и доступ

  • admin — полный доступ, настройки, пользователи, архив, API-токен.
  • viewer — только разрешённые камеры; без изменения настроек.
  • Пароли и API-токен хранятся в config.yaml; не публикуйте файл.
  • Для интеграции используйте отдельный токен и заголовок X-API-Token.
  • SSO-cookie vhs_sso используется для перехода между сервисами VHS.
Смените пароль администратора и security.api_token сразу после установки. Не оставляйте значения из config.example.yaml.

Интеграция и API

VHS-Viewer получает список потоков из Streamer, а VHS-Security — состояние из Viewer. Streamer не требует Security для работы.

МетодНазначение
GET /api/integration/streamsсписок камер и WebRTC-URL для Viewer
GET /api/streamsпотоки и RTSP/WebRTC-ссылки
GET /api/statusсостояние сервера

Пример: 

curl -H "X-API-Token: <security.api_token>" \
  http://127.0.0.1:{{ port }}/api/integration/streams

ARM / Jetson: установка

Для AIE100-T2NX (Jetson TX2 NX) используется JetPack 4.6 / Ubuntu 18.04 / Python 3.6. Установщик сам создаёт runtime/py36, понижает синтаксис и ставит совместимые зависимости. 

cd VHS-Streamer-ARM-USB
chmod +x install_jetson.sh start.sh stop.sh
./install_jetson.sh --service
# для доступа из локальной сети:
./install_jetson.sh --service --open-ports

После установки проверьте: 

systemctl status vhs-streamer
curl http://127.0.0.1:{{ port }}/health
journalctl -u vhs-streamer -n 100 --no-pager

ARM: диски и нагрузка

  • 16 ГБ eMMC недостаточно для видео — используйте NVMe M.2 2280.
  • Архив — только на внешнем носителе; локальный буфер минимальный.
  • TX2 NX: 4 ГБ RAM, 4–8 камер 1080p без транскодирования.
  • YOLO/ALPR на TX2 NX не запускайте — аналитика остаётся на Viewer.
  • NVENC требует Jetson-патчей FFmpeg; иначе кодирование идёт через libx264.

ARM: миграция по SSH

Скрипт migrate_to_arm.sh переносит Streamer на другой ARM: копирует комплект, устанавливает службу и переносит данные.

  1. Подготовьте SSH-ключ и вход без пароля.
  2. Разрешите sudo без пароля для установки пакетов и systemd.
  3. Запустите миграцию с флешки или со старого сервера.
./migrate_to_arm.sh user@new-arm \
    --data-from /opt/vhs-streamer \
    --stop-source

--data-from указывает каталог старой установки. Скрипт переносит config.yaml, archive/ и events.db. Перед копированием архива остановите старый экземпляр — иначе можно скопировать незавершённый сегмент.

Не запускайте миграцию одновременно с записью в архив. После переноса проверьте /health, камеры и свободное место.

ARM: ограничения

  • JetPack 4.x не обновляется до Ubuntu 22.04/24.04 официально.
  • Python 3.6 EOL: не выставляйте Streamer напрямую в интернет.
  • 4 ГБ RAM ограничивают число камер и motion detection.
  • Для 10+ камер или AI используйте Orin/x86-сервер.
  • Проверьте температуру и питание: Jetson нельзя отключать «из розетки».
